# ASR → LLM 重写 → 剪映草稿

适用于从已有音频、视频或第三方口播进入人物故事再制作的项目。

## 固定流水线

```text
最终音频
  ↓
本机 Coli ASR，只保留原始转写和 token 时间
  ↓
LLM 理解、事实整理、结构重组和仿写
  ↓
新的 narration.txt，作为本期唯一正文
  ↓
豆包 TTS 重新生成新的 narration.mp3
  ↓
对新 MP3 再跑一次 Coli，获得新音频的时间依据
  ↓
用新 narration.txt 生成字幕文字，并用新 ASR 的时间边界定位
  ↓
用新 narration.txt 拆分镜和生成图片
  ↓
用同一版 narration、SRT、图片和 MP3 导出剪映草稿
```

## 输入和版本边界

- 原始 ASR 文本保存为 `asr-raw.txt` 或 transcription 版本目录中的原始 JSON/SRT。
- LLM 的提示词保存为 `aicost-rewrite-prompt.md`，返回结果保存为独立版本的 `narration-aicost-rewrite.md`。
- 通过事实、字数和风格检查后的新正文保存为 `narration.txt`。
- 新配音只读取 `narration.txt`。原始文案、第三方稿和旧版 narration 不能作为新配音正文。
- 新配音完成后，Coli 的识别文字只用于时间定位和音文差异记录。不能把 ASR 错字直接写进新字幕。

## LLM 重写要求

提示词至少说明人物、事实边界、目标时长、开头钩子、写作风格和输出格式。要求模型先理解 ASR 内容，再重新组织叙事，不能逐句改错或沿用原稿句序。人名、地名、机构名、数字和引语进入事实复核清单，模型补出的内容不能自动视为事实。

## 新稿与时间轴

新稿是字幕、分镜旁白和草稿计划的文本源。新 ASR 是时间源。两者出现差异时，保存原始 ASR、差异记录和采用的时间证据，不能用字符数量重新均分音频，也不能为了让自动脚本通过而篡改新稿。

如果自动边界无法可靠匹配，状态写为 `review_required`。可以按可靠 token 时间、局部核听或人工确认建立新的对齐版本，完成后再导出草稿。

## 交付要求

- 每个版本目录同时保留 `narration.txt`、新 MP3、新 ASR JSON/SRT、字幕来源说明、`STORYBOARD.json`、`plan.json` 和语义核验记录。
- 新版本使用新草稿名，不覆盖旧草稿。
- `semantic_alignment.json` 中记录当前 MP3、当前字幕、当前图片和当前旁白文本的哈希及版本关系。
- 旧图片只有在与新旁白的人物、时期、地点和动作逐镜匹配后才能复用。无法确认时标记 `pending`，不能写成已核验。
